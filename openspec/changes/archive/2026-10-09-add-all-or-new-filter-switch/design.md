## Context

Static Astro site; every season page renders the same component chain (`[season].astro` → `Layout` + `CategoryNav` + `CategorySection`/`ShowCard` + `QuickStats`). `CategoryNav.astro` is the sticky filter bar: category pills with per-category counts on ≥ 768px, a hamburger + slide-down panel below. All interactivity today is tiny `is:inline` scripts — the theme toggle in `Layout.astro` established the pattern: `data-theme` attribute on `<html>`, `localStorage` persistence with try/catch, and a synchronous head script that applies the stored value pre-paint (FOUC prevention, required by the design-tokens spec). No runtime JS framework; output must stay static with no runtime external requests; all styling via `var(--*)` tokens; boards are read-only at build.

Marker facts (verified by parsing): `parseBoard` extracts only the `*(marker)*` form into `markers`, and marker matching throughout the site (`QuickStats.astro`, the badge rendering) is exact (`markers.includes('continuing')` / `includes('movie')`). **Fall 2026 parses to 80 shows: 9 continuing long-runners (2 exact markers + 7 with inline `(continuing)` inside the bold title, invisible to the parser), 20 sequel premieres (no marker of any kind — no sequel marker exists), 4 movies (inline `(movie…)` in titles), 51 brand-new.** QuickStats on fall currently reads "New / sequels: 78, Continuing: 2, Movies: 0" — all three figures wrong under the redefined "new". **Summer 2026 parses to 63 shows: 5 exact `continuing` markers, 7 variant continuing markers (`continuing from Spring` ×6, `continuing from Winter` ×1), 16 unmarked sequel premieres, 42 brand-new; no inline-title debt.** Summer also carries free-form compound markers (`movie + tv series`, `netflix movie`) that don't exact-match `movie`.

See proposal.md — Why for motivation and the brand-new definition.

## Goals / Non-Goals

**Goals:**
- An "All / Only New" switch inside the existing filter bar, working in both nav modes, keyboard-operable, token-styled, with zero new dependencies.
- "Only New" = brand-new shows only: `continuing` and `sequel` markers both hide a show; unmarked shows stay.
- Both live boards carrying the markers that drive the filter (fall: 31 line edits; summer: 16), so `/fall-2026/` and `/summer-2026/` filter consistently and QuickStats agrees with the screen by construction.
- A no-flash, persisted client filter that degrades to "All" without JavaScript; quick-stats that describe the whole board with New/Sequels split into separate figures.

**Non-Goals:**
- No search, pagination, per-service/movie filters, or sorting — future work.
- No parser or marker-syntax changes (`*(marker)*` stays the contract; boards are fixed, not the parser).
- No URL/query-param filter state (static pages; client state only).
- No changes to enrichment, season routing, or deploy.
- No redefinition of variant markers (`continuing from Spring/Winter`, summer's compound movie markers) — exact-match only, same as today; deferred to Open Questions.

## Decisions

### D1: Filter state is a `data-show-filter` attribute on `<html>`; CSS performs the hiding
**Choice:** `ShowCard.astro` adds `data-continuing` (when `markers` includes `continuing`) and `data-sequel` (when `markers` includes `sequel`) to its `<article>`. A global CSS rule hides returning cards whenever the filter is active: `[data-show-filter='new'] .card[data-continuing], [data-show-filter='new'] .card[data-sequel] { display: none; }`. Toggling the filter is one attribute write on `document.documentElement` — exactly the `data-theme` pattern. The same card change renders the "Sequel" badge next to the existing "Continuing"/"Movie" badges.
**Why:** Zero per-card JavaScript, instant application, no DOM surgery, and the same mechanism the site already uses for theming. The rule must live in a global style context (Layout's `is:global` block or `:global()` in CategoryNav) because Astro scopes component styles. The Sequel badge mirrors the existing badge pipeline so users can see why a card vanishes under "Only New".
**Alternatives:** A script looping over cards to set `style.display` (more JS, state-sync on every toggle); server-rendering a second, pre-filtered page variant (doubles output, complicates routing); query-param-driven filtering (needs JS anyway, no per-user persistence); hiding only `data-continuing` and looping in sequels via JS (two hiding mechanisms, drift risk).

### D2: The switch lives in CategoryNav; per-category counts are baked at build time
**Choice:** `[season].astro` already maps categories into nav items; it passes `{ name, slug, count, newCount }` where `newCount = shows.filter(s => !s.markers.includes('continuing') && !s.markers.includes('sequel')).length` — the brand-new count, the same predicate the filter and QuickStats use. Pills and mobile panel items carry `data-count-all` / `data-count-new`; `CategorySection` keeps its anchor `id={slug}` so the script can find each section from its pill's `href="#<slug>"`. The switch is a two-button segmented control inside CategoryNav: `<div role="group" aria-label="Show filter">` with "All" and "Only New" `<button>`s exposing `aria-pressed`, styled like the existing monospace pills with the accent-based active state used by season pills. On desktop it sits in `.catnav-wrap` after `.catnav-inner` (pinned right, outside the horizontally scrolling pill row); on mobile it sits in the `.catnav-mobile` row next to the hamburger, so it never requires opening the panel.
**Why:** Counts are build-time facts — baking them as data attributes keeps the client script trivial (swap numbers, toggle `hidden`), and the section lookup via existing anchor ids needs no new wiring. Native buttons give keyboard support for free; the segmented pill control matches the site's established nav language.
**Alternatives:** A `<select>` (heavier than two states warrant); a checkbox toggle (less discoverable, doesn't match the pill bar's look); placing the switch in the site header next to the theme toggle (far from the category bar whose contents it filters — the user asked for the filter bar).

### D3: Stored preference applies pre-paint; a small CategoryNav script owns the toggle
**Choice:** The existing synchronous head script in `Layout.astro` additionally reads `localStorage.getItem('showFilter')` and, when it equals `'new'`, sets `document.documentElement.dataset.showFilter = 'new'` before first paint (wrapped in the same try/catch; anything else leaves the default "all"). A second small `is:inline` script in `CategoryNav.astro` (mirroring the hamburger script) wires the buttons: on click it flips the attribute, persists the value, syncs both buttons' `aria-pressed`, and runs a `syncUI()` that, for every category, writes the active count into pill/panel labels and toggles `hidden` on the pill, the panel item, and the section when the active count is 0. `syncUI()` also runs once on load so a persisted "new" state produces correct counts immediately. The hiding itself is pure CSS (D1), so the script only moves counts and visibility of nav/section shells.
**Why:** Applying the attribute pre-paint prevents a flash of unfiltered content for returning "new" users — the exact FOUC-prevention pattern the design-tokens spec already mandates for theme. Keeping the toggle script colocated with the bar follows the CategoryNav hamburger precedent.
**Alternatives:** Applying the filter on `DOMContentLoaded` (visible flash); not persisting (simpler, but the theme-toggle precedent says users expect the choice to stick); a shared site-wide script file (new asset, against the tiny-inline-script grain of the codebase).

### D4: "Only New" shows brand-new shows: hidden iff `continuing` or `sequel` marker (exact match)
**Choice:** One predicate everywhere — filter, per-category counts, and the QuickStats "New" figure: a show is brand-new iff its `markers` include neither `continuing` nor `sequel` (exact matches, no prefix/substring). Unmarked shows — including movies and TV specials that carry only a `movie` marker or nothing — stay visible.
**Why:** The spec scenarios require the on-screen result to agree with QuickStats ("New"); a single shared predicate guarantees that by construction. Exact matching is the site's established convention, and it keeps `continuing from Spring`-style variants stable and predictable. Movies/specials are one-off season events, not series carryovers — they stay visible; the board owner can still mark an unnumbered franchise follow-up (e.g. a sequel movie) with `*(sequel)*` if they want it hidden.
**Alternatives:** Title-regex heuristics for sequels (fragile: "Prince of Tennis II" vs "(2024)" remakes vs split-cour labels; invisible to unnumbered franchise continuations — rejected); a `*(new)*` marker on ~51+42 brand-new lines (inverted default: more edits, and every future board line must remember to opt in — drift-prone); prefix-matching `continuing*` (silently redefines the established stat; deferred to Open Questions); hiding sequels only on fall (inconsistent behavior across the only two live boards — rejected, hence the summer pass).

### D5: Fix the boards, not the parser — one marker pass per board, with a human review checkpoint
**Choice:** Boards are the human-edited source of truth; markers are the machine contract between them. Three mechanical, content-preserving transforms:
1. **Fall — 7 inline `(continuing)` titles** → `*(continuing)*` marker form (Beyblade X, One Piece, Red River, Rilakkuma, Odekake Kozame Season 2, Pocket Monsters (2023) / Pokémon Horizons, Nezumi-kun no Chokki Season 2), matching the two already-correct lines (Detective Conan, Meitantei Precure).
2. **Fall — 20 sequel premieres** gain `*(sequel)*` (Reincarnated as a Sword S2, A Wild Last Boss Appeared! S2, A Returner's Magic Should Be Special S2, Sasaki and Peeps S2, Reincarnated Aristocrat S3, Black Clover S2, Apothecary Diaries S3, Blue Box S2, Ranma ½ (2024) S3, The Ramparts of Ice S2, Chitose Ramune Part 2, HOTEL INHUMANS S2, Mission: Yozakura Family S2 Part 2, Aoashi S2, Prince of Tennis II: U-17 World Cup, Ace of Diamond Act II — 2nd Season Cour 2, Kizudarake no Seijo S2, plus the review-checkpoint additions Cyberpunk: Edgerunners 2, Tokyo Revengers: War of the Three Titans Arc, and Tougen Anki: Nikko Kegon Falls Arc).
3. **Fall — 4 movie lines** → exact `*(movie)*` marker (Witch on the Holy Night, The Apothecary Diaries Movie: Bouhi no Hihou, Maebashi Witches: Emoemories, BanG Dream! Ave Mujica: Prima Aurora), with release-date text kept readable in the title or blurb. Exact form matters: `*(movie, Oct 22)*` would NOT exact-match the existing `includes('movie')` predicates.
4. **Summer — 16 sequel premieres** gain `*(sequel)*` (Mushoku Tensei S3, Re:ZERO S4, Slime S4, Tanya S2, Skeleton Knight S2, Hell Mode S2, Trapped in a Dating Sim S2, Old Country Bumpkin S2, Clevatess S2, Polar Opposites S2, 100 Girlfriends S3, Hana-Kimi S2, Elusive Samurai S2, Grand Blue Dreaming S3, Azur Lane: Slow Ahead! S2, plus the review-checkpoint addition Bleach: Thousand-Year Blood War Part 4 — The Calamity). Its continuing shows and variant markers are untouched.
**Review checkpoint:** the title scan that produced these lists is conservative (it can miss unnumbered franchise continuations), so the board owner confirms the full list before commit. Judgment calls the plan already takes a stance on: Odekake Kozame S2 / Nezumi-kun S2 stay `continuing` (the board author's existing marks — short-form shows that roll continuously); Mission: Yozakura Family S2 Part 2 gets `sequel` (split-cour second part of a fall-premiering season); Prince of Tennis II: U-17 gets `sequel` (franchise continuation premiere); the Conan TV special and My Happy Marriage Special Episode stay unmarked/visible (new one-off fall events, not series carryovers); Maebashi Witches: Emoemories gets only `*(movie)*` (movie, visible) — the owner may add `*(sequel)*` if they want it hidden. **Checkpoint outcome (2026-10-09):** the owner confirmed four additional sequels — Cyberpunk: Edgerunners 2, Tokyo Revengers: War of the Three Titans Arc, and Tougen Anki: Nikko Kegon Falls Arc (fall), and Bleach: Thousand-Year Blood War Part 4 — The Calamity (summer). Candidates that stay unmarked (brand-new) per the owner's calls: STEEL BALL RUN (2nd STAGE continues), the Bonobono shorts block, BAKI-DOU, Sgt. Frog 2026, Dragon Ball Super: Beerus, and other unnumbered franchise entries.
**Why:** The boards simply don't conform to the marker contract the parser is specified against, and no sequel marker existed. Normalizing gives clean titles, badges, a self-corrected QuickStats (New 51 / Sequels 20 / Continuing 9 / Movies 4 on fall), and every returning show filterable. Parser untouched means `parseBoard` tests and all other boards are unaffected; summer gets the same pass so both live pages behave identically.
**Alternatives:** Teaching the parser to strip inline `(continuing)`/`(movie)` from titles (loosens a specified contract, changes behavior for every board, muddies title vs marker semantics); title heuristics in the filter (see D4); fall-only marker pass (summer's sequels stay visible — inconsistent); leaving data as-is (the feature ships visibly broken on exactly the page it was requested for: only 2 of 29 returning shows would hide).

### D6: Empty categories disappear while "Only New" is active; QuickStats does not react
**Choice:** `syncUI()` hides a category's pill, panel entry, and section when its active count is 0, and restores everything on "All". The quick-stats footer is never touched by the filter — it always describes the whole board (as spec'd).
**Why:** This is now load-bearing, not hypothetical: Fall 2026's SPORTS category (Aoashi S2, Prince of Tennis II, Ace of Diamond Act II Cour 2, Beyblade X) contains zero brand-new shows, so under "Only New" it empties on exactly the motivating page. A category heading over an empty grid is noise, and a pill that scrolls to nothing is a dead link. Stats stay whole-board because they are season-level facts, and the "New" figure is what proves the filter's result.
**Alternatives:** Keeping empty sections visible (clutter + dead anchors); filtering the stats too (misrepresents the season and contradicts the quick-stats requirement).

### D7: QuickStats splits "New / sequels" into "New" and "Sequels", computed from markers
**Choice:** `QuickStats.astro` computes `continuing`, `sequels`, and `movies` by exact marker match, and `new = total − continuing − sequels` (identical predicate to D4/D2, expressed as the complement). The footer's merged "New / sequels" figure is replaced by two figures — "New" and "Sequels" — joining Total, Continuing, Movies, and Links resolved (grid goes from 5 to 6 stats; the ≥ 640px grid-template-columns widens accordingly, mobile stays 2-column). Per-service counts, links-resolved, and the prose-stats `<details>` are unchanged.
**Why:** The redefined filter must agree with the stats, and a merged figure can't describe a three-way split (brand-new / sequel / continuing). Computing from markers (rather than trusting board prose) is already the spec'd behavior; the markers now exist to make it truthful. Fall self-corrects: "New / sequels: 78, Continuing: 2, Movies: 0" → "New: 54, Sequels: 17, Continuing: 9, Movies: 4".
**Alternatives:** Keeping the merged figure plus a new "Brand new" stat (redundant, confusing); trusting the boards' prose stats (contradicts the existing quick-stats requirement); not splitting (filter and stats disagree — rejected by the spec scenarios).

## Risks / Trade-offs

- [Sequel identification is judgment-laden] → The 20/16 lists come from a conservative title scan (numbered seasons/parts) plus the human review checkpoint, which caught four unnumbered continuations the scan missed. Mitigation: the completed checkpoint confirmed the final lists; going forward, marking returning shows is part of board maintenance.
- [Board edits touch human-curated content — 47 lines total] → Mechanical, content-preserving transforms (titles stay verbatim; parentheticals become markers); verified by re-parsing (fall: 80 shows, 9 continuing, 20 sequel, 4 movie; summer: 63 shows, 5 continuing, 16 sequel) and a `git diff` review before commit.
- [Fall QuickStats figures change observably] → Intended: New 51 / Sequels 20 / Continuing 9 / Movies 4 replaces "New / sequels: 78 / Continuing: 2 / Movies: 0"; the prose-stats `<details>` still preserves the board's own words.
- [Hiding cards mid-scroll changes page height] → Acceptable: the toggle is explicit user intent; scroll position is preserved, counts update in place. If the user is scrolled into SPORTS when it empties, the section vanishes under them — restored exactly on "All".
- [`localStorage` unavailable (privacy modes)] → try/catch swallows the error; the filter falls back to per-session behavior, defaulting to "All". No content is ever unreachable.
- [Summer's compound movie markers (`movie + tv series`, `netflix movie`) don't exact-match] → Summer's Movies figure stays 0 after this change, exactly as today; same deferred variant-marker class as `continuing from Spring` (Open Questions). Not silently redefined.
- [Shared `showFilter` key applies the preference across season pages] → Intended: one site, one mental model (theme behaves the same way). If seasons ever need divergent defaults, the key can gain a season prefix later without spec changes.
- [No JavaScript] → Page renders in "All" with everything visible; the switch buttons are inert. No degradation of content access.
- [Scoped-style escape required for the global hide rule] → The rule goes in a global style context; a task verifies the built CSS actually contains both unscoped selectors (Astro scoping is easy to get wrong).

1. Ship components first: `ShowCard` (`data-continuing` + `data-sequel` + Sequel badge), `CategorySection`, `CategoryNav` (switch UI + `syncUI` script), `Layout` (pre-paint read), `[season].astro` (brand-new count threading), `QuickStats` (split figures + 6-stat grid). Build and preview both season pages — with unmarked boards, the switch already works for the 5 marked continuing shows.
2. Fall board marker pass (7 continuing + 20 sequel + 4 movie lines, D5); re-run the parse check (80 shows; 9 continuing, 20 sequel, 4 movie markers; clean titles; diff shows only intended lines).
3. Summer board marker pass (16 sequel lines); re-run the parse check (63 shows; 5 continuing, 16 sequel; 42 brand-new).
4. Verify end-to-end: 375px / 768px / 1280px, keyboard toggling, persisted reload (no flash), counts/sections reacting (SPORTS hides and restores), QuickStats correct for both boards and unchanged by the filter, `BASE_PATH` build unaffected.
5. Commit boards + components together as one revertible unit.

**Rollback:** Single git revert — no cache, schema, asset, or deploy changes.

## Open Questions

- Should variant markers (`continuing from Spring/Winter`, summer's `movie + tv series` / `netflix movie`) eventually be normalized or taught to the predicates, so older season pages filter and count them too? Deferred — today the exact-match convention keeps filter and stats consistent everywhere; changing it is a separate, deliberate convention shift.
- Should "Only New" (and QuickStats' figures) eventually grow more states or splits (e.g. "Only Movies", per-service)? Deferred — the segmented control and `syncUI` shape extend naturally, but nothing in this change requires it.
- Should the persisted preference ever be per-season instead of site-wide? Deferred — site-wide matches the theme toggle; revisit only if boards diverge in behavior.
- Convention going forward: do unnumbered franchise continuations (reboots, "Shin <title>" entries) count as brand-new by default? Plan's stance: yes, unmarked = brand new; the board owner marks returning entries `*(sequel)*` when they read as returning rather than new.
